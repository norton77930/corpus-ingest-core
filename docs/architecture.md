# Architecture

> The Hermes sidecar audit chain (specs 026-034) terminated at BLOCKED and was removed from `main` on 2026-08-29. Its modules, specs, deployment files, scripts, and evidence are preserved in full under the git tag `archive/hermes-audit-chain`.

This document reflects the Phase 7C system shape. Podcast Ingestion Core is still a thin-CLI / thick-core Python package, but the repo now includes a research layer, optional LLM paths, MCP exposure, deterministic eval / review gates, official Spec Kit bootstrap files, and a project-specific Spec Kit constitution.

## Core Principles

- CLI scripts parse arguments and call `podcast_ingest_core` core functions; runtime behavior belongs in the package.
- Podcast-specific configuration stays in `config/podcasts.yaml`; core modules must accept a generic `podcast_id`.
- Source artifacts remain local files under `data/`; SQLite cache and eval reports are derived or audit artifacts.
- Side-effect operations are dry-run first where practical. LLM calls require explicit acknowledgement.
- Research outputs must separate podcast evidence, deterministic inference, external verification status, and LLM-generated synthesis.
- Phase 7A is documentation/spec stabilization only: no runtime behavior change, no MCP behavior change, no LLM call, and no `.env` read.
- Phase 7B bootstraps official Spec Kit scaffold: `.specify` stores memory/templates/scripts/workflow metadata, `.agents/skills` stores Codex `$speckit-*` skills, and `AGENTS.md` stores repo-level agent instructions.
- Phase 7C is Spec Kit Constitution + Workflow Alignment: `.specify/memory/constitution.md` and `.specify/templates/` encode the project gates for dry-run, exact LLM acknowledgement, evidence separation, external-data status, no live market API, no `.env` read, and no investment advice.
- Future feature work should use the full Spec Kit flow: `$speckit-constitution`, `$speckit-specify`, `$speckit-clarify`, `$speckit-plan`, `$speckit-checklist`, `$speckit-tasks`, `$speckit-analyze`, `$speckit-implement`, and `$speckit-converge`; `$speckit-taskstoissues` is only for GitHub issue handoff.
- Phase 7D is Spec Kit Backfill via Full Workflow: `specs/README.md` maps existing capability-group backfill packages such as `002-ingestion-transcript-core` and `006-llm-safety-synthesis-smoke-review` to roadmap phases, modules, CLI/scripts, and tests. This remains docs/spec/tests only with no runtime behavior change, no MCP behavior change, no LLM call, no `.env` read, no live market API, and no investment advice.
- Phase 7D.1 is Spec Kit Active Feature Guidance: feature packages live under `specs/<feature>`, while `.specify/` stores scaffold, memory, templates, scripts, integration, and workflow metadata. `SPECIFY_FEATURE_DIRECTORY` selects a package explicitly and takes precedence; `.specify/feature.json` is optional local-only, gitignored, and untracked state. This is Spec Kit command usability documentation only with no runtime behavior change, no `.env` read, no live market API, and no investment advice.
- Phase 6U semantic summary smoke validates the transcript-transfer LLM path through dry-run-first smoke CLI and deterministic review gate. Confirmed execution requires exact `api_cost_ack`; CLI output keeps no raw transcript stdout, no MCP behavior change, no live market API, and no investment advice.
- Phase 6V reviewed semantic context is optional for stock lens synthesis. Default synthesis remains `phase-6f-stock-lens-json-only`; opt-in synthesis may read only review-passed `.semantic.md` metadata/final summary context and marks `phase-6f-stock-lens-json-plus-reviewed-semantic-summary`, with no raw transcript, no live market API, no MCP behavior change, and no investment advice.
- Phase 6V.1 aligns the research LLM smoke review gate with boundary/context consistency: JSON-only synthesis must have no semantic context, and reviewed semantic synthesis must include non-empty, review-passed semantic context.

## Current Module Groups

- ingestion: `feed_reader.py`, `downloader.py`, and `transcriber.py` list episodes, download audio, and create transcript artifacts. A podcast profile now carries a `source_type` (default `rss`); `feed_reader` and `downloader` refuse non-RSS sources with `UnsupportedSourceTypeError` rather than failing on an absent `rss_url`.
- non-RSS acquisition: `x_video_ingest.py` (Spec 036) turns an X video URL into an audio asset plus an episode seed, then reuses `transcribe_episode(audio_path=..., title=...)`. It is dry-run-first and adds no transcription or transcript-emission code of its own. `segment_grouping.py` merges transcript segments into 30-90s reading blocks as a pure function; the result is computed on demand and never persisted.
- transcript validation and summaries: `validator.py`, `summarizer.py`, and `semantic_summarizer.py` validate transcript status, create deterministic extractive summaries, and optionally create LLM semantic summaries. `summary_profiles.py` (Spec 037) holds the prompt shapes as pure data and selects one per podcast through an additive `PodcastProfile.summary_profile` (default `finance`, plus `learning-notes`). The profile varies only what the LLM is asked to produce and the `## 摘要限制` body; the rendered envelope — Metadata block, `Summary mode: semantic-llm`, `## Chunk Summaries` — is a downstream contract and is identical for every profile.
- mentions and search: `entity_extractor.py`, `cache.py`, and `search.py` create deterministic mentions and index/search transcripts and mentions.
- research reports: `episode_intelligence.py`, `industry_mapping.py`, `external_data_boundary.py`, `external_data_verification.py`, `gooaye_lens.py`, and `stock_lens.py` build deterministic research artifacts from existing local sources.
- LLM synthesis and smoke review: `stock_lens_synthesis.py`, `research_workflow.py`, `research_llm_smoke_review.py`, and `semantic_summary_smoke_review.py` support optional LLM synthesis, workflow orchestration, the Phase 6T review gate, and Phase 6U semantic summary smoke review.
- corpus status and remediation: `corpus_episode_intake.py` bootstraps one RSS-resolved episode into local seed metadata; `corpus_index.py` and `corpus_remediation_plan.py` expose package-private pure build snapshots plus the existing atomic persist boundaries; standalone `corpus_audio_download_runner.py`, `corpus_local_transcription_runner.py`, and `corpus_remediation_runner.py` still refresh/persist index and plan before previewing or executing; `corpus_episode_workflow_runner.py` builds one in-memory snapshot and uses package-private previews for zero-file selection, then confirmed execution dispatches exactly one existing public runner.
- standalone semantic remediation: `corpus_semantic_remediation_runner.py` evaluates one explicit episode from exactly one in-memory 008/009 snapshot. Dry-run is strict zero-file. Confirmed execution requires an explicit `semantic_summary` or `semantic_review`, calls exactly one existing executor, writes a confirmed-only latest report with no `generated_at`, and does not call 010 or 014.
- human-controlled completion: `corpus_episode_completion_workflow_runner.py` selects one safe action across intake through semantic review. Its dry-run is strict zero-file and uses one in-memory snapshot for seeded episodes; confirmed execution requires a canonical episode and one explicit action, dispatches exactly one existing public runner, writes a metadata-only latest report, and stops.
- latest deterministic processing: `corpus_latest_episode_deterministic_workflow_runner.py` is the implemented request-bounded flow that locks one canonical latest episode, advances only local deterministic stages, and stops before semantic summary. SPEC 017 is Implemented. The 2026-07-17 `seeded`/`downloaded` mapping defect is a resolved historical blocker; the recorded EP679 metadata-only confirmed outcome is `ready_for_semantic_summary`.
- latest verified research reporting: `latest_episode_verified_research_report_workflow_runner.py` validates episode-scoped `expected_episode_ref` and exact acknowledgement before protected access, reuses the pinned 017 helper, gates semantic review at exact `passed`, then invokes fixed-safe deterministic research. `verified_research_report.py` validates source/provenance, calculates a digest version, and atomically publishes/reuses/fails closed a JSON/Markdown/manifest bundle with metadata-only checkpoint support.
- interfaces: scripts under `scripts/` are thin CLIs; `mcp_runtime.py` owns the single `FastMCP` instance, `mcp_tools_*` registers the exact 25-tool surface, and `mcp_server.py` is the compatibility facade. Existing clients use stdio; `run_mcp_http_server.py` serves the same instance over loopback-only Streamable HTTP.
- shared contracts: `models.py`, `storage.py`, `errors.py`, `llm_provider.py`, `llm_profiles.py`, `local_env.py`, and `serialization.py` hold common data, paths, errors, provider settings, local `.env` loading, and JSON serialization.

## Data Flow

1. ingestion reads RSS metadata and writes audio/transcript files under `data/audio/` and `data/transcripts/`.
2. transcript validation classifies transcript status before summary or research steps run.
3. deterministic summaries and optional LLM semantic summary write `data/summaries/`.
4. deterministic mentions write `data/mentions/` and can be indexed into SQLite cache.
5. episode intelligence reads transcript metadata and mentions, then writes `data/reports/`.
6. industry mapping reads episode intelligence plus local mapping config, then writes `data/mappings/`.
7. external boundary writes `data/external/` with `not_requested`, `not_fetched`, and `data_date=null` until external checks are performed.
8. local fixture verification can update external boundary metadata from `config/external_market_data_fixtures.yaml`; this is a local fixture path, not a live provider.
9. stock lens reads podcast-wide mapping and external boundary artifacts, then writes `data/stock-lens/`.
10. LLM synthesis optionally reads Phase 6F stock lens JSON only and writes `.stock-lens-synthesis.*`.
11. Phase 6T review gate reads existing synthesis artifacts and writes deterministic review reports under `evals/research-llm-smoke/reports/`.
12. Phase 6U semantic summary smoke review reads existing `.semantic.md` artifacts and writes deterministic review reports under `evals/research-llm-smoke/reports/`.
13. Corpus episode intake resolves `latest` or one explicit configured RSS episode in dry-run, writes no files in dry-run, and writes only local seed metadata plus `data/corpus/{podcast_id}/corpus-episode-intake-run.json` and `.md` after confirmation.
14. Corpus artifact index reads only local per-episode artifact paths/metadata, episode seed metadata, and latest semantic review status, then writes `data/corpus/{podcast_id}/corpus-index.json` and `.md` without raw transcript, evidence, semantic body, RSS, SQLite cache, `.env`, network, LLM, or MCP changes.
15. Corpus remediation plan refreshes the corpus index, derives full-ladder missing artifact actions, blockers, warnings, and optional/gated semantic actions, then writes `data/corpus/{podcast_id}/corpus-remediation-plan.json` and `.md` without executing remediation commands.
16. Standalone corpus remediation runner refreshes and persists the 008/009 index/plan even in dry-run, returns selected/skipped/blocked/excluded metadata without executing generators or writing its own run report, and writes `corpus-remediation-run.json/.md` only for confirmed bounded execution.
17. Standalone corpus local transcription runner likewise persists fresh 008/009 in dry-run, previews local-audio transcript gaps without transcription or its own report writes, and writes `corpus-local-transcription-run.json/.md` only after a confirmed single-episode attempt.
18. Standalone corpus audio download runner likewise persists fresh 008/009 in dry-run, previews missing-audio candidates without RSS/network/downloader/audio/own-report writes, and writes `corpus-audio-download-run.json/.md` only after a confirmed single-episode attempt or explicit selection rejection.
19. Corpus fresh episode workflow runner resolves intake from configured RSS or builds one fresh in-memory index/plan snapshot for seeded previews. Its dry-run is strict zero-file across every artifact and `.part`; confirmed `stage=next` dispatches exactly one existing 013/012/011/010 public runner and then writes `corpus-episode-workflow-run.json/.md`.
20. Corpus semantic remediation requires an explicit canonical episode. `semantic_summary` validates exact api_cost_ack before profile, summary-profile, `.env`, credential, or provider resolution; deterministic `semantic_review` touches no LLM configuration. Both stop after one executor and do not rebuild persisted 008/009 or SQLite cache.
21. Corpus episode completion performs a strict-zero-file preview across intake, audio, local transcription, deterministic remediation, semantic summary, and semantic review. A confirmed request recomputes selection, rejects drift, executes one explicit action, writes `corpus-episode-completion-workflow-run.json/.md`, and does not rebuild index, plan, or cache.
22. MCP tools expose read/search, selected side-effect tools, research workflow, verified research report workflows, the offline catalog query, source revalidation, episode-centric coverage, and historical next-step suggestion. The current reviewed local stdio registry contains exact 25 tools: Tool 25, `derive_workflow_bundle`, is append-only after unchanged Tools 1–24; its preview is zero-write and zero-network, and confirm calls an LLM and needs the exact `api_cost_ack`. Tool 24, `ingest_youtube_video`, is the YouTube ingest tool. Tool 23, `ingest_x_video`, remains the X ingest preview/confirm tool and previews with a public-metadata network read (zero-write, not zero-network). Tool 22, `generate_stock_lens_report`, remains a dry-run-first side-effect stock lens (no LLM, no `api_cost_ack`, no network, no live market API, no investment advice). Tool 21 `list_verified_report_gap_backlog` remains a read-query inventory gap backlog. Tool 20 remains historical next-step suggestion. Tool 19 remains coverage join. Tool 18 remains exact-locator offline revalidation. Tool 17 retains its catalog contract; inspect fixes `source_currentness_status=not_evaluated`.
23. Latest deterministic episode workflow resolves `latest` exactly once in each confirmed run, then uses the canonical episode for intake, audio download, local transcription, and deterministic remediation. It stops on failed/blocked work and at `ready_for_semantic_summary`; it does not create an LLM/provider, perform semantic summary/review, retry, batch, schedule, or rebuild cache.
24. Latest verified research reporting previews with strict zero-write behavior, then validates exact `expected_episode_ref` and exact `api_cost_ack` before RSS, environment/provider, writers, or child stages. It pins latest once, requires semantic review `passed`, uses fixed safe research options, writes bounded checkpoint metadata, and atomically publishes digest-versioned `report.json`, `report.md`, and `manifest.json`; matching bundles are reused while conflicts fail closed.
25. Spec 036 X video ingestion resolves source metadata only in dry-run, so the plan costs no download and no transcription. A confirmed run downloads with a guest token into a temporary directory outside `data/`, extracts a mono 16 kHz WAV into `data/audio/{podcast_id}/`, writes the episode seed with `seed_source=x-video`, and then calls the existing transcriber. The source video never becomes a corpus artifact, no credential is accepted or stored, and the SQLite cache is not rebuilt.

26. Spec 039 adds YouTube on the same acquire stack (`video_acquire.py` + `youtube_video_ingest.py`, `seed_source=yt-video`) and closes the source-type seam: remediation treats `{x-video, yt-video}` missing audio as blocked for RSS download, 012/014/016/017 refuse that dispatch, and local transcription uses the plan/index title. Episode refs may contain `_`. No MCP tool is added.

## Execution Modes

- deterministic steps: ingestion after user command, transcript validation, extractive summary, mention extraction, episode intelligence, industry mapping, external boundary, stock lens report, cache indexing, Phase 6T review gate, Phase 6U semantic summary smoke review gate, corpus episode seed intake, corpus artifact index generation, corpus remediation plan generation, confirmed single-episode corpus audio download runs, confirmed local transcription runs, confirmed deterministic corpus remediation runs, and confirmed one-stage corpus fresh episode workflow runs.
- optional LLM steps: semantic summary and stock lens synthesis. These require `confirm=True` and the exact API-cost acknowledgement before provider construction; `run_semantic_summary_smoke.py` dry-run keeps no raw transcript stdout. Phase 6V semantic context in synthesis is explicit opt-in and uses only review-passed semantic summary context, not raw transcript or live market data.
- local fixture step: external data verification currently supports only `provider="fixture"` and reads local YAML fixture data.
- not implemented: no live market API, no automatic market data provider, no scheduler, no web UI, no embedding/vector search, and no investment advice engine.

## Safety Boundaries

- Stock lens synthesis uses `phase-6f-stock-lens-json-only` by default and does not read raw transcript. Phase 6V opt-in may use `phase-6f-stock-lens-json-plus-reviewed-semantic-summary` with review-passed semantic context only.
- Semantic summary is the only current path that may send transcript text to an LLM, and only after explicit acknowledgement.
- `.env` is local convenience configuration for CLI use; it must not be committed and must not appear in docs, eval reports, or MCP responses with values.
- External boundary status fields are availability/status markers, not market facts.
- Reports must preserve no investment advice: no buy/sell/hold recommendation, no target price, and no guaranteed return.
- Phase 6T review gate is heuristic and deterministic. It helps catch obvious boundary violations but does not replace manual review.
- Corpus episode intake is seed-only and dry-run first: dry-run may read configured RSS to resolve a selector but writes nothing; confirmed execution writes only local seed metadata and a run report, omits unsafe feed details, and must not download, transcribe, call LLM/MCP, run downstream remediation, or rebuild cache automatically.
- Corpus artifact index is status metadata only: it may report paths, counts, missing artifacts, unreadable JSON warnings, and latest semantic review status, but must not copy transcript/evidence/semantic body text and must not add MCP tools in v1.
- Corpus remediation plan is plan-only metadata: it may report missing artifacts, blockers, warnings, ordered manual action text, and optional/gated semantic remediation, but must not execute downloads, transcription, summaries, workflow steps, LLM calls, MCP tools, or cache rebuilds.
- Corpus remediation runner is dry-run first and filter-bounded: standalone dry-run persists fresh 008/009 but writes no own run report and executes no generator; confirmed execution requires an episode or action-family filter and remains deterministic-only.
- Corpus local transcription runner is dry-run first and single-episode bounded: standalone dry-run persists fresh 008/009 but writes no own report/transcript and loads no model; confirmed execution requires one episode and explicit local audio.
- Corpus audio download runner is dry-run first and single-episode bounded: standalone dry-run persists fresh 008/009 but writes no own report/audio and reads no RSS/network/downloader; confirmed execution requires one episode and calls only the existing downloader.
- Corpus fresh episode workflow runner is dry-run first and one-stage bounded: 014 dry-run is zero-file, recomputes state once in memory, and exposes only safe local read paths or the two exact non-path labels; confirmed execution requires `stage=next`, dispatches exactly one existing public runner, records that result, and must not execute semantic/LLM, MCP registry, cache rebuild, stock-lens, batch, or non-selected stages.
- Corpus semantic remediation is standalone: it preserved the then-current exact 12 MCP tools at the time it landed, does not call 010 or 014, does not rebuild index/plan/cache, excludes force/partial/batch/retry/scheduler/full-chain behavior, and is not investment advice.
- Corpus episode completion is a human-controlled boundary: dry-run is strict zero-file, confirmed mode rejects `next`/`latest` and stale selections, one explicit action is dispatched at most once, and the portable Skill may only use the reviewed MCP tool rather than a CLI/terminal fallback, retry, scheduler, or autonomous loop. The 016 MCP addition changed the reviewed registry to exact 13 tools at the time, while retaining manual cache refresh and no investment advice.
- Corpus latest deterministic processing is a request-bounded boundary: its portable Skill makes exactly one confirmed MCP call, the Core pins one canonical latest episode, and it stops before semantic work. The 017 addition changed the reviewed registry to exact 14 tools while retaining manual cache refresh and no investment advice.
- Latest verified research reporting is a human-controlled episode-scoped boundary: preview is strict zero-write, and confirmed mode requires matching `expected_episode_ref` plus exact acknowledgement before protected access. It may use only the existing acknowledged semantic path, review must be `passed`, research has fixed safe options, and a source-digest JSON/Markdown/manifest bundle is atomically published/reused/fail-closed. The 018 addition set the reviewed registry to exact 15 tools; it has no live market API, retry, scheduler, automatic cache rebuild, raw-transcript report content, or investment advice.
- Explicit-episode verified research reporting (019) previews readiness for a named `episode_ref` and confirms assemble/publish only when lineage and review already pass. It does not require `api_cost_ack`, does not call LLM/RSS/download, and does not chain 015–017. The 019 addition changed the reviewed registry to exact 16 tools at the time.
- Verified research report catalog (020) is offline read-only and manifest-first: list/search use only safe metadata projections (no report/transcript/source body reads); inspect verifies local self-consistency only and fixes `source_currentness_status=not_evaluated`. Tool 17 is append-only read-query; the registry after 020 was exact 17 tools.
- Verified research report source revalidation (021) accepts only the exact `(podcast_id, episode_ref, source_digest)` locator, keeps bundle validity separate from source currentness, never dereferences hostile path strings, and writes nothing. Tool 18 is append-only read-query.
- Verified research report coverage (022) joins local inventory episode refs with 020-safe bundle summaries for one exact `podcast_id`, optionally filters `has_bundle`, and never reads report bodies or writes files. Tool 19 is append-only read-query. The reviewed local stdio MCP registry after 022 landed was exact 20 tools; Tools 1–18 contracts and order were preserved. Historical counts above (12–18) describe the registry at the time each package landed, not the current total.
