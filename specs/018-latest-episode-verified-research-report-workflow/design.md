# Design: Verified Research Report Assembly and Publication

## Execution Boundary

`confirm=False` resolves one canonical latest episode and constructs a plan in memory. It is strict zero-write: no checkpoint, report directory, staging directory, child stage, environment/provider, or external verification access.

`confirm=True` first checks a non-empty `expected_episode_ref` and exact `api_cost_ack`. It then resolves latest once and rejects drift. Drift is an approval-boundary rejection, not a terminal checkpoint outcome: it creates no expected/latest checkpoint, claim, staging directory, or bundle. Only after these guards can it enter the pinned deterministic ladder, semantic gate, research gate, checkpoint writer, or report publisher. This is an episode-scoped human approval boundary, not authorization for retries, scheduling, batches, force, or another episode.

## Stage Gates

After approval and latest-reference pinning, the workflow derives the stable episode checkpoint path and acquires an episode-workflow claim before any provider, LLM, child fixed-path output, checkpoint reservation, or bundle inspection. The claim combines an in-process keyed mutex with the persistent cross-process OS lock, so two threads in one process cannot re-enter an advisory process lock. It is held through the terminal result; different episode claim paths remain parallel.

1. Inside the episode claim, complete artifact/bundle adoption validates transcript, strict canonical transcript selection, full lineage, fixture/stock requirements, and bundle bytes before reading checkpoint metadata. A corrupt checkpoint cannot veto this adoption.
2. Pinned 017 local deterministic processing returns only an acceptable ready state and uses the same strict canonical transcript resolver. Multiple identity-valid title variants require one valid external corpus episode seed; 018 lineage and bundle manifests are derived outputs and never transcript trust roots. Otherwise the episode blocks.
3. Semantic summary is reused only with current direct transcript lineage or generated once when absent/untrusted. A newly controlled summary records progressive lineage; an unreadable summary blocks rather than being relabelled as reusable.
4. A centralized semantic inspector recomputes the canonical evaluator result from immutable current transcript-title-bound summary bytes. It accepts a review only when timestamped JSON exactly records that result plus matching identity, exact `passed`, and additive `semantic_summary_sha256`. Missing/stale/spoofed/forged apparently-passed review artifacts select one safe deterministic re-review; only current `passed` and review lineage continue.
5. Deterministic research is invoked with fixed safe options and status exactly `completed`. Missing/mismatched research lineage cannot be blessed from reused legacy files; all affected roles must be newly controlled or independently lineage-valid. Progressive semantic lineage permits safe later-stage resumption without trusting downstream legacy bytes.
6. Assembly recomputes the complete lineage gate (including current fixture marker and stock corpus input set), then validates artifact identity and quality/provenance before publication.

A blocked, rejected, failed, unknown, unreadable, or identity-mismatched stage returns a bounded terminal outcome. No later stage runs.

## Atomic Publication

The assembler produces deterministic JSON and Markdown from a digest-versioned source set. The publisher creates a short random staging directory beneath the final bundle parent, writes `report.json`, then `report.md`, then `manifest.json`, rereads each file, and hashes it. It atomically renames the complete directory to its final version path.

If final content already exists, a per-bundle exclusive claim covers comparison through return. The publisher validates the exact three-file directory, deterministic JSON and Markdown bytes, and the full expected manifest (identity, options, sources, gates, and metadata). The digest includes immutable bytes and canonical normalized source paths, while the manifest retains selected source-path provenance; therefore an authentic re-review at a new path publishes a distinct auditable version. An exact valid match is reused only after another bundle and source revalidation immediately before success returns. Any conflict, extra file, coordinated report/manifest tampering, source mutation, or nonmatching manifest fails closed. Sources are revalidated after staging validation and immediately before rename. If a destination appears during rename, this same complete validation determines reuse; otherwise the race fails closed. Bundle and checkpoint claims are process-lifetime OS locks: Windows locks byte zero with `msvcrt`, POSIX uses nonblocking `flock`, and the stable lockfile may remain after close or crash. After drift approval, the checkpoint claim atomically reserves the next episode-local integer generation before any child stage. All confirmed writes carry that generation; a stale successful writer merges history but retains a higher successful generation's bundle metadata. A legacy no-generation checkpoint is generation zero. A checkpoint write after successful rename may be retried by a later artifact-driven run, which adopts/reuses the valid bundle rather than republishing.

## Report Safety

Safe formatting removes raw transcript text, credentials, URI query/fragment content, and traceback bodies. AWS secret assignments, private-key headers, credential/token/password assignments, direct personalized investment advice, and unsafe source text fail closed before a final report can publish. The low-level `report_safety` guard is shared by neutral semantic review and assembly: it blocks direct `You should`, `I recommend`, imperative `consider buying`, and common `推薦/建議/值得` buy/sell/hold variants, but permits a historical transcript reference only where an explicit attribution precedes a matching quote pair on the same line. Neutral review has no stock-lens, provider, or LLM import. Timeline facts retain sanitized evidence with timestamp and segment provenance; the stock appendix separately retains sanitized direct evidence, inferred leads, and verification details. Public filters and result serialization are recursively bounded and never reflect credential-like values or arbitrary objects. It labels evidence by classification and never converts external status into a market fact. It has no live market API and no investment advice. `expected_episode_ref` and exact `api_cost_ack` are only confirmation controls; acknowledgement text and secret-like values are not report content.
