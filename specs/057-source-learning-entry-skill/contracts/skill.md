# Source learning entry contract

Entry selects one explicit learning request. Known prepared IDs go to source-content-qa; one supported configured URL gets prepare_learning_source(confirm=false) once. Read source-preparation's response contract and the entry reference before validating preparation/status replies. The entry is its own bounded coordinator, not execution of the standalone source-preparation Skill with its stop rules overridden.

Ready preview needs validated status, exact identity and readiness time; legal non-executable context_digest does not permit confirm. Fresh Tool35 inspect must verify that identity/readability before QA. Preparation needed requires all effect/settings disclosures and fresh approval. Confirm uses exact canonical URL and plan_id once, validates accepted identity/settings, reports safe job_id, retains the original request and stops. No polling or automatic post-submit learning.

Status-only asks call inspect_source_preparation_job once and stop. Explicit continuation uses retained job/source/request; check job_id and IDs, ready/validated status, readiness time and configured/recorded settings validity before fresh Tool35 inspection. Busy job_id may belong elsewhere and is never attached to this source. Tool34 does not return URL/source_type, so never require or fabricate them. Unknown/lost/ambiguous context requires clarification. In_progress may retain a compatible job reference but stops until later explicit continuation.

QA must load the installed source-content-qa Skill and its response/template references. Version/chunk continuity, cumulative budgets, partial scope, hostile-source handling, language mismatch, no advice, host privacy/billing and optional project application remain intact. Query errors never initiate preparation or repair. Missing required same-server tools or installed resources stops; no terminal/filesystem execution fallback, installation or service/settings change. Skill resources may be read by the host normally; managed corpus/settings reads must use reviewed tools.

Existing tool signatures/count/order and both standalone Skills remain unchanged. Chat notes never publish a formal lecture/derivation; provider acknowledgement boundaries remain separate. The current repository can establish offline/SDK evidence only; actual Hermes acceptance remains a separate recorded execution gate.
