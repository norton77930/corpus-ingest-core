# Research decisions

Tool35 in source_content_query.py and source-content-qa/references/response-contract.md define prepared-source/version/ordinal/chunk evidence. The ignored057 helper proved SDK delivery but hardcodes a source/path and prints evidence; it is not the portable operator command.

- Actual SDK rather than direct Core read exercises transport/registry/data-root choice. In-memory adversarial sessions test failures. Neither proves Hermes model compliance.
- Separate command rather than validate_mcp_setup: that validator requires SQLite/broad legacy workflows; prepared QA has no cache prerequisite. Preserve existing behavior.
- Explicit owned stdio or existing numeric-loopback HTTP: no arbitrary command, public listener, installation/settings read. Credentials/query/fragment/redirect/proxy fallback rejected.
- Metadata-only stdout: no title/transcript/cursor/server-error/exception strings. Only finite validated identity/version/settings/counts/status.
- Complete three Skill folders: recursively verify relative references; one notes template. Inventory is distinct from loading/installing.
- No implicit live preparation: verification consent is not consent to an undisclosed source plan. Retain live gates.

Rejected: copying pilot into default data, auto config repair, direct transcript fallback, new tool, deployment, semantic scoring as replay substitute, hardcoded inventory that misses future links.

Fresh read-only reviewer reproduced raw HTTP SDK parser-body logging, SDK GET reconnect, reference-style resource omissions and valid time-range ordinal gaps. Focused RED then fixes: scoped temporary logging filters on both adapters, httpx pre-dispatch duplicate request guard, Markdown definitions, strict increasing selected ordinals with exact chunk offsets/counts. Existing query/Skill contracts are unchanged. Range-selection gaps arise from non-monotone end times with monotone starts, supported by actual Tool35 selector.
