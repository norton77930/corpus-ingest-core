# Research: X Video Ingest MCP Tool

**Date**: 2026-08-19

## 1. 004 → 035 is the exposure precedent

Spec 004 shipped stock lens Core + CLI. Spec 035 added Tool 22 as a last-imported
group module. That is the required shape: thin wrapper, append-only, snapshot
regenerated by script.

Decision: copy 035, do not append into `mcp_tools_side_effect.py` (that would
insert at slot 13).

## 2. Preview is zero-write, not zero-network

Spec 036 Safety already recorded this. Corpus runners promise no network on
dry-run. X preview calls yt-dlp metadata so the plan has a real title and knows
whether a video exists.

Decision: keep `"dry_run": true` on the MCP envelope; set result `run_mode` to
`preview`; add `network_read` fields; document the distinction. Do not make MCP
preview local-only URL parse (the plan would be fictional).

## 3. Confirm scope

Core `run_x_video_ingest(confirm=True)` already downloads, extracts, writes the
seed, and transcribes. Splitting acquire vs transcribe would be a new Core
capability.

Decision: wrap the existing function. Hide GPU/device/work_dir on MCP. Accept
that CPU confirm can run for minutes.

## 4. Result gaps

`XVideoIngestResult` lacks `run_mode` and `not_investment_advice`. No confirmed
report is persisted. Every `Corpus*RunResult` has both.

Decision: add the two fields; persist JSON+Markdown via `write_part_staged_report_pair`
on confirm only. Per-episode paths under the podcast corpus directory.

## 5. Registry chain

035 listed the blast radius: AST source file list + size 22, deny adapter 22,
descriptor snapshot, docs-count checker, setup docs, registry contract tests.

Decision: add `mcp_tools_x_video.py` to `_MCP_TOOL_SOURCE_FILES`, change 22→23
at those sources, regenerate the snapshot. Do not hand-edit JSON. Do not run
Hermes live.

## 6. YouTube

039 shipped YouTube CLI with no MCP, and named 040 as the X-ingest candidate.

Decision: X only. YouTube MCP is a later spec that can copy this envelope.
