# Consent cycle and acceptance data
Cycle states: need_identity -> preview_once -> stopped(blocked/complete/invalid) OR await_consent -> wait/clarify/cancel OR confirm_once -> terminal_report. Silence/ambiguous consent does not create another preview. Target/plan/request change invalidates cycle; a later explicit request may start another. Calls are exactly0/1preview and0/1confirm,onlyTool32. No runtime controller/persisted state.
Approved binding: explicit podcast_id/episode_ref, returned next_action/plan_id, planned artifact/reuse/lineage/report paths,cost class,fresh user reply. Cover uses emptyack;generation forwards freshly provided exact string. The SHA256-shaped plan is opaque metadata,not content/authentication/lock.
Dialogue fixtures: unique id,scenario category,action or malformed/terminal fixture,user reply class,expected calls/next-state/response classification,rule refs,sensitive markers. Oracles are expected traces,not actual agent runs. Characterization tests use realTool32 replies and existing owned temporary fixtures/fake providers. No arbitrary evaluation scripts in production.
