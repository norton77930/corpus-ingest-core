# 來源學習筆記範本

這份 Markdown 是 `source-content-qa` 的可編輯預設範本。可持續調整深度、順序與欄位；本次使用者的格式要求優先。修改本檔可改變後續筆記的預設格式，已產生的筆記不會自動重寫。已載入舊版的 Agent 需要重新讀取；若 Hermes 使用獨立副本，需同步這個 references 目錄與 SKILL.md。

## 如何整理

- 以影片或 Podcast 本身的議題為中心。每個議題說清楚討論的問題、講者的推理與實際例子，讓初學者能理解；一句主題標籤不足以取代說明。依來源內容安排議題數與篇幅，避免只為填滿欄位而補內容。保留關鍵例子與比喻的具體情境、角色或動作，並說明它如何支持觀點，不要壓縮成只有抽象結論。
- 講者觀點與影片例子必須有逐字稿支持。無法辨識發言者時寫「講者」，不要猜測身分。逐字稿未明確標示性別時，用「講者」或來源確認的名字，不推測「他／她」等性別代名詞；聲音、主題或帳號名稱不是判斷依據。沒有提供推理或例子時，明說來源未提供，或省略該欄。
- 必要的名詞解釋標示「AI 補充解釋」；自行設計的示例標示「AI 補充例子，非影片內容」，與影片中的例子分開。所有 AI 補充都放在明確標示的獨立段落，不混入講者觀點或來源例子。學習重點是原文歸納；新的判斷或建議另標「AI 延伸」。
- 正文預設只整理來源議題。不新增使用者未要求的段落，例如特定對象摘要、專案應用或其他額外交付；範本的選填欄位不代表必須填寫。「套用到專案」預設省略；使用者要求應用時，放在獨立選填欄位或附錄，標示「AI 建議」，使用已提供的專案脈絡。
- 用段落解釋主題，再用表格彙整回聽段落。閱讀範圍、完整／部分狀態與 ASR 限制依實際證據填寫；範本本身不構成完整閱讀的證明。

## 筆記骨架

**本集主題：**〔依原文寫出主要討論方向〕

**來源與閱讀範圍：**〔來源名稱；實際讀取的時間範圍；完整或部分筆記〕

**逐字稿與核對限制：**〔已知轉錄資訊與實際核對方式；未回聽音訊就明說〕

以下依實際議題重複，無需維持固定議題數：

**議題：〔名稱〕｜〔MM:SS–MM:SS 或 HH:MM:SS〕**

**這段在討論什麼：**〔交代問題或背景，讓沒有看過影片的人也能理解〕

**講者如何說明：**〔依原文交代觀點、理由與前後關係；保留不同意見與限制〕

**影片中的例子：**〔轉述實際出現的例子；未提供例子時省略或明說〕

**AI 補充解釋／例子（需要時）：**〔用白話解釋陌生名詞；自擬例子明確標成非影片內容〕

**學習重點（依原文歸納）：**〔說明這段值得理解的觀念，避免把未提出的建議歸給講者〕

**值得回聽的原因：**〔指出值得注意的推理、例子或分歧〕

**套用到專案（選填，AI 建議）：**〔僅在使用者要求時加入；與原文及一般學習解釋分開〕

**回聽清單**

| 時間 | 議題 | 回聽時注意什麼 |
|---|---|---|
| 〔實際時間〕 | 〔議題〕 | 〔值得核對或複習的內容〕 |

## 調整方式

可在本次請求指定「名詞解釋多一點」、「每個議題寫完整推理」、「保留影片例子」或「另外加專案應用欄」。這些是單次格式要求，不會自動改寫本檔。想改變長期預設時，編輯這份範本，或明確請 Agent 更新；保留来源／AI 補充的區分與實際閱讀範圍。
